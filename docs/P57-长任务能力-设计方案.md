# P57 长任务能力设计方案（Agent 通用长任务能力 + 分阶段路线）

> 状态：**设计稿（待评审）** · 日期：2026-08-28
> 目标域：**通用长任务**（部署 / 迁移 / 批量运维 / 排障 / 数据处理流水线……凡几十步、状态耦合、易丢目标者皆属），不以任何具体任务（如 Hadoop）为绑定点。

---

## 1. 背景与问题

当前 Agent 是经典 ReAct 循环：模型单步输出命令 → 执行 → 回读 → 下一步。对**长任务**有 5 个通用致命伤：

| # | 难点 | 现状表现 |
|---|------|---------|
| 1 | **长程上下文衰减** | `max_history` 裁剪后模型忘目标、忘已做步骤 |
| 2 | **状态强耦合** | 每步依赖前一步产物/路径/端口，错一步崩一串且不自知 |
| 3 | **需结构化操作+自校验** | 裸 shell 改配置无回读校验，错误隐蔽 |
| 4 | **预检需并行看多源** | 一条条串行查询，往返多、时滞长 |
| 5 | **失败恢复差** | 中途失败从头再来或反复重试同一条命令 |

其中 **1 与 5 是通用第一性问题**，2/3/4 部分被任务类型放大。本方案先解通用层，不留建领域工具。

---

## 2. 设计目标 / 非目标

### 目标
- **让 Agent 能从头到尾、多步、不丢目标地完成一条长任务**；中途失败只重规划失败的子集，不重做、不回退、不从头。
- 保持现有状态机 / 计划卡 / 危险确认 / 记忆账本架构，**不推翻、只增量**。
- 本地弱模型（gemma4:26b 等）可用：协议用**弱约束格式**而非强 JSON function-calling。

### 非目标（本期不做）
- **不做领域工具层**（改 xml/查服务的"工具化"）——它是正交、后置的，等有具体高频痛点再按领域追加。
- 不做同会话多执行体（沿用 §8.2 决议：每会话单执行体 + 跨会话 name 隔离）。
- 不做跨会话任务编排 / 断点续跑持久化到磁盘（本期任务图仅存于当前 job 内存）。

## 3. 分层架构

```
┌─────────────────────────────────────────────┐
│ L3 领域工具层（后置,按需追加,正交）            │
│   file.patch / svc.* / pkg.* ...            │
├─────────────────────────────────────────────┤
│ L2 子目标任务图（★核心新增,通用骨架）          │
│   任务→子目标拆解 → 逐目标推进 → 失败子集重规划 │
├─────────────────────────────────────────────┤
│ L1 记忆账本（已落地,P57 前序）                │
│   已完成/失败步骤账本,每步注入防遗忘            │
└─────────────────────────────────────────────┘
```

- **L1**：已实现（`ai_job.rs` 的 `ledger` + `build_progress_summary`，agent_step 注入），通过 75 项测试。
- **L2**：本方案的主体新增。
- **L3/L4**：记录为后置候选，不进本期实现清单。

## 4. L2 子目标任务图：详细设计

### 4.1 核心机制

一次长任务划分为**有限个子目标**（goal），每个子目标内包含若干命令。状态机从"平坦命令流"升级为"按子目标组织的推进"。

```
任务: "全新部署 Hadoop (隔离目录)"
 ├─ 子目标1 预检环境(JDK/端口/磁盘/二进制)      → {java -version; free -h; ...}
 ├─ 子目标2 解包安装到 /opt/helm-hd-test          → {mkdir; tar -xzf; ln -s ...}
 ├─ 子目标3 配置 env + 3 个 xml                   → {export HADOOP_HOME; edit core-site...}
 ├─ 子目标4 格式化 NameNode + 启动                  → {hdfs namenode -format; start-dfs.sh...}
 └─ 子目标5 自校验并回读结论                       → {jps; hdfs dfsadmin -report}
```

**推进规则**
- 每轮只推进**当前子目标**：模型先给出"当前要做的事 + 对应命令"。
- 当前子目标内命令执行完/失败 → 标记该子目标 `ok | failed`，再让模型决定：进入下一子目标 / 修正当前子目标内的失败命令。
- **失败只重规划当前子目标内的命令**：失败不影响已 `ok` 的旧子目标，向后不重做。
- 子目标级**一次性计划卡**确认（沿用你已定的"整组放行 + 危险命令逐条兜底"裁决）。

### 4.2 数据结构（Rust 草案）

在 `core.rs` 引入任务图类型：

```rust
/// 单个子目标的状态
pub struct SubGoal {
    pub id: u32,
    pub title: String,          // 模型起的短标题,如 "解包安装到 /opt/helm-hd-test"
    pub status: SubGoalStatus,  // Pending | Active | Ok | Failed
    pub cmds: Vec<String>,      // 该子目标内的命令(由模型给出,当前计划卡的来源)
}

pub enum SubGoalStatus { Pending, Active, Ok, Failed }

/// 任务图:一次长任务的结构化拆解(仅存于当前 job 内存)
pub struct TaskGraph {
    pub task: String,
    pub goals: Vec<SubGoal>,
    pub cursor: usize, // 当前 active 子目标下标
}
```

`AiPayload` 增事件（前端据此渲染"分目标卡"）：

```rust
AiPayload::GoalStarted { name, goal_index, title }
AiPayload::GoalDone    { name, goal_index, status: SubGoalStatus }
```

### 4.3 状态机扩展（映射现有 §8.7.1 状态）

| 现有状态 | 在任务图下的含义 |
|---------|-----------------|
| `Parsing` | 模型产出"子目标拆解 或 当前子目标的命令" |
| `Planning` | 对**当前子目标**整组广播计划卡 |
| `AwaitingConfirm` | 子目标级一次性确认（沿用裁决） |
| `Executing` | 执行当前子目标内命令 |
| `ReadingBack` | 标记当前子目标 ok/failed，决定下一个子目标 |

关键差异：原本"每步一个计划卡"改为"**每子目标一个计划卡**"，一次性把该子目标的多条命令整批放行，减少串行确认次数，同时仍逐条危险兜底。

### 4.4 模型协议（弱约束，对本地弱模型友好）

**首次**（无 current_task）：
```
新任务：<task>
请先把这个长任务拆解成不超过 N 个子目标。
每行一个子目标，格式：GOAL <序号> <短标题>
（最后给当前第一个子目标要执行的命令，仍需只输出命令）
```

**推进**（已有任务图）：
```
子目标进度：{已完成 ok 的目标} / {当前目标} / {失败目标}
要执行的命令：...
```

> 抗回显：所有 `GOAL`/提示文字用独立前缀标记，`parse_commands` 里按"仅解析命令行、忽略 GOAL/进度/摘要"过滤，规避已知的提示词回显死循环。

### 4.5 与记忆账本衔接

- `SubGoal.title` 与每命令执行结果（成功/失败+要点）共同写入 L1 账本摘要，注入推进轮。
- 账本从"平坦命令列表"升级为"按子目标分组的命令列表"，模型读起来更结构化。

### 4.6 安全

- 新增 `write`/`patch` 类结构改写**本期不引入**（属于 L3），故无新增危险面。
- 子目标级计划卡"整组放行"沿用现有裁决：整组批准=对当前子目标整组命令的一次性显式授权；`Edit` 复位回退；`confirm_all` 恒逐条。危险命令绝不静默执行。

## 6. 分阶段路线图（每阶段一次隔离长任务真机验收）

| 阶段 | 内容 | 改动量 | 验收 |
|------|------|--------|------|
| L1（已完成） | 记忆账本 | — | 75 测试通过,真机冒烟通过 |
| **L2-alpha** | `TaskGraph` 数据结构 + `SubGoal` 解析 + 逐目标推进 + 失败子集重规划 + `GoalStarted/GoalDone` 事件 + 分目标计划卡 | 中等 | 隔离"全新部署"长任务:目标可拆、失败只修子集、不重做已完成 |
| L2-beta | 前端分目标卡/进度条 | 中等 | 活动流可按子目标分组浏览 |
| L3（后置,待痛点） | 领域工具 + 弱约束工具协议 | 大 | 以真实高频操作为例回读自校验 |
| L4（可选） | 并行预检 | 小 | 预检阶段一次并跑多条只读命令 |

> 验收场景用一个**隔离目录 + 全新长任务**（例如在 `/opt/helm-hd-test` 做一次全新部署，验证后清理），避免触碰已有 master/Hive/HBase 环境。验收判据：**能自动拆目标、能跨多步保持目标、失败时只修正当前子目标、不重做已完成目标**。

## 7. 风险与回退

- **风险1 本地模型拆解质量不稳**：中低风险。预案：`N` 子目标上限 + `SubGoal` 解析容错（拆不出就降级回"平坦命令流"，行为与现状一致）。
- **风险2 子目标一次计划卡过长**：某子目标命令太多导致计划卡臃肿。预案：单子目标命令数上限，超出则强拆。
- **风险3 提示词回显死循环**（项目已知坑）。预案：所有非命令行加独立前缀、解析层严格过滤命令行（沿用 `parse_commands` 白名单思路）。
- **回退**：L2 全部落在增量层，`TaskGraph` 为空时完全走回现有平坦循环，可一行开关整体回退，无迁移成本。

## 8. 决策记录（ADR）

- **D1**：先做通用长任务能力（L2），不做领域工具（L3）——L2 对任何长任务生效，L3 正交后置。
- **D2**：任务图仅存 job 内存，不落盘——本期无断点续跑需求，接口预留持久化位。
- **D3**：确认粒度 = 子目标级整组放行 + 危险命令逐条兜底，沿用 P56 裁决。
- **D4**：模型协议用弱约束格式（前缀标记 + 命令行白名单过滤），不用强 JSON function-calling，适配本地弱模型。

## 9. 调研优化（2026-08 联网,并入 L2 的设计增量）

> 依"联网调研 → 与本地 8~26B 弱模型可行性交叉 → 取舍"得出。只并入**低成本高收益**者；高成本/弱模型不友好者明确放弃。

### 9.1 采纳（并入 L2 实现清单）

**增量1 · Reflexion 反思块（补"失败为什么"）**
Reflexion 用自然语言反思（哪步错了/为何/下次怎么改）替代权重更新，对执行型 agent 是明确的失败恢复剂 [arXiv:2303.11366](https://arxiv.org/pdf/2303.11366)。
落地：命令失败后追加一条 `<reflexion>失败原因→修改策略</reflexion>` 入账本；下次循环先读反思再执行。本地弱模型开销约 ~200 token/失败，无需额外模型/检索。

**增量2 · 执行后独立校验（不靠模型内省）**
纯内在自修正常把对的改错（缺外部信号时自修正更差 [ICLR2024](https://zylos.ai/research/2026-05-12-agent-self-correction-reflexion-to-prm/)）。
落地：为**子目标**挂**确定性校验表达式**（退出码 / 输出含关键字 / 文件/端口存在），由后端校验器执行；子目标 `Ok` 判定 = 校验器通过，而非模型自称。校验失败 → 该子目标置 `Failed` 并带原因进账本。

**增量3 · 防"过早收敛 / 重复循环"（终止判断硬化）**
长时程基准指出最常见失败是两个：模型提前宣布完成、原地重复循环 [UltraHorizon](https://www.alphaxiv.org/abs/2509.21766)。
落地：a) 模型声明 DONE 时要求提供完成证据，后端过校验器才真正结束；b) 强化现有失败熔断——连续失败即停（已有 `invalid_steps`），并**禁止自动重试已失败的高危命令**。

**增量4 · 子目标 checkpoint / 幂等 / 回滚**
生产 agent 推荐 Stage→Validate→Commit + 人工 interrupt + 安全回滚 [LangGraph 两阶段提交](https://www.marktechpost.com/2025/12/31/how-to-design-transactional-agentic-ai-systems-with-langgraph-using-two-phase-commit-human-interrupts-and-safe-rollbacks/)。
落地：子目标计划卡在"命令"外并列**预期结果 + 回滚操作**；每个子目标完成后存一个 checkpoint（索引 + 状态），失败可回退到上一 checkpoint 重演；高危写操作强制幂等检查。

**增量5 · 阶段摘要压缩（ACON 思路）**
轨迹压缩到高密度摘要可降 token 26%~54% 且保性能 [ACON](https://openreview.net/forum?id=7JbSwX6bNL)。
落地：每子目标完成或每 N 步，把详细账本压缩成一段摘要（已完成/当前状态/待办/约束），替换累积细账；**人工规则兜底**至少保留"当前目标 + 最后成功/失败步骤"，防弱模型压缩过度。

### 9.2 明确放弃（弱模型不划算）

| 项 | 理由 |
|----|------|
| 完整 MemGPT 三层记忆 / 向量库 | 弱模型 self-editing 不稳、本地 embedding 内存开销大 |
| ReWOO 全量批量规划 / Tree-of-Thoughts | 依赖依赖图或树搜索,弱模型把图画崩/推理成本过高 |
| 硬拆两层 Planner/Executor | 弱模型 Planner 战略不稳;当前子目标图已近层次化,不再加层 |
| 纯 Self-Refine / 模型自夸式完成 | 无外部信号,弱模型更容易"自己说服自己"→ 已被增量2/3 取代 |

### 9.3 修正后的 L2 状态机流转

```
Parsing(出子目标/命令 + 预期结果 + 回滚)
  → Planning(子目标卡:命令+预期+回滚, 整组确认)
  → AwaitingConfirm(沿用 P56 裁决)
  → Executing(逐命令; 失败写 <reflexion>)
  → 校验(退出码/关键字/文件)  → Ok 置该子目标, checkpoint++
        └ 失败 → 该子目标 Failed + 原因入账本, 只重规划当前子目标
  → ReadingBack(阶段摘要压缩, 喂下轮) → Pending(完成则 DONE, 需校验通过)
```

### 9.4 对 P57 落地顺序的影响

L2-alpha 的验收判据在"能拆目标/失败只修子集/不重做"基础上，追加：**能给出预期校验并客观判成败、不靠模型自夸、失败给原因、不提前 DONE**。
