## 2. P99 缺陷修复(2 项必修 + 1 项防御性,建议立即做)

### P99-1 文件面板 `cdReq` effect 的多余依赖(**已降级:P0 → P1;真机未能复现"回跳"**)

- **原判**(静态分析):`cdReq` 的 `$effect` 内经 `resolvePath()` 读取响应式 `cwd`;`refresh()` 会写 `cwd` → 自身被再次触发,用过期目标再刷一次 → 面板"回跳"。
- **真机实测结论(2026-10-09,10.0.0.10)**
  1. `MutationObserver` 逐帧监听 `.fs-cwd`:**双击进目录未见任何回跳**(唯一一次变化是我主动点「上一级」)。
  2. 临时埋点(`window.__cdEff` 计数)证明 **effect 确实会重跑**:每次面板导航计数 **+2**(一次来自 cdReq 变化,一次来自 cwd 变化),终端 cd 同样 +2。
  3. 但那次多出来的 `refresh(旧目标)` **被 `refreshSeq` last-write-wins 丢弃**了 —— 因为面板导航同时会 `syncTerminal` 发 `cd '<新目录>'`,远端 OSC7 回包引发的**新刷新先一步启动**,旧刷新结果 `seq !== refreshSeq` 直接 return,不写 DOM。
- **因此实际影响**:(a) 每次导航多一次 SFTP 往返(`fs_list_dir` + `fs_current_dir`)被浪费;(b) **潜在**回跳只在"过期刷新先落地而新刷新更晚启动"时出现 —— 即**慢链路**(SFTP 往返 < 远端 OSC7 往返)或**非 bash Linux 会话**(无 OSC7,没有更新的刷新来取代它,会稳定停在旧目标)。
- **依据**:[FileBrowser.svelte:87-93](../../frontend/src/components/files/FileBrowser.svelte) + [:138-140](../../frontend/src/components/files/FileBrowser.svelte) + [:63-65](../../frontend/src/components/files/FileBrowser.svelte) + [:56/:61/:64/:71](../../frontend/src/components/files/FileBrowser.svelte)(seq 守卫)
- **改法(仍建议做,属防御性 + 省一次 IPC)**:`import { untrack } from "svelte"`,effect 内 `const target = untrack(() => resolvePath(r.target));`,注释写明"此 effect 只依赖 cdReq.seq,不得引入 cwd"。
- **验收(按新认识调整)**
  1. 埋点计数:面板导航时 `__cdEff` 不再 +2(只 +1);等价地,一次导航只产生一组 `fs_list_dir/fs_current_dir` 调用。
  2. 行为不变:终端 `cd /var` → 面板 /var;面板双击 → 面板停在新目录且终端同步。
  3. 无网络替代验收:抽 `resolveTarget(raw, cwd, sep)` 纯函数补 Vitest 用例。
- **风险**:低(仅隔离依赖,不改刷新时序)。

### P99-2 AI 回显丢消息(终端未建时的 seq 空洞)**✅ 已完成(2026-10-09,Vitest 35 项)**
- **落地**:新增纯函数 `frontend/src/lib/echo.ts::replayEcho(entries, cursors, hasTerm)` → `{writes, next}`,**按会话独立游标**且不修改入参;TerminalTabs 的 `$effect` 改为调用它(`lastEchoSeq` 由 number 改 `Map<会话, seq>`);`echo.test.ts` 6 个用例覆盖"低 seq 不被同批更高 seq 越过""终端建立后补写滞留条目""死会话不阻塞其它会话""幂等""不改入参"。前端测试 29 → 35。

- **现象**:多会话并行时,某会话终端晚建,其低 seq 回显被永久丢弃(如"[连接失败] 原因"不回显)。
- **根因**:循环里终端不存在时 `continue`(不推进 seq 是对的),但**同帧内后续更高 seq 会推进 `lastEchoSeq`**,于是低 seq 条目下轮被 `<=` 永久跳过 —— 与 632-634 注释的"保留待写"意图相反。
- **依据**:[TerminalTabs.svelte:635-647](../../frontend/src/components/terminal/TerminalTabs.svelte)
- **改法**:数组按 seq 升序,遇缺失终端即停止推进(而不是继续处理更高 seq);或按会话维护 `lastEchoSeq[name]`。抽纯函数 `replayEcho(entries, lastSeq, hasTerm)` 返回 `{writes, nextSeq}`,组件只做副作用。
- **验收**:Vitest 新增用例 —— entries `[{seq:1,A},{seq:2,B}]`、`hasTerm(A)=false`、`hasTerm(B)=true` → `nextSeq` 不得越过 1,且 A 在终端建立后能补写。
- **风险**:低–中(回显顺序),需保证 `termVersion` 重放路径仍生效。

### P99-3 `ctl_rx` 关闭导致的 CPU 忙循环 **✅ 已完成(2026-10-09,`cargo test` 127 项)**
- **落地**:抽出 `async fn drive_step<F,T>(fut, ctl_rx) -> Driven<T>`(`Returned`/`Cancelled`/`ControlClosed` 三态),FC 与文本两条路径复用;`ControlClosed` 视同终止(emit `Done{已停止}` + `finished = true`)。3 个 `#[tokio::test]` 锁定语义:通道关闭 200ms 内必须返回、陈旧 Approve/Reject 不得终止任务、Cancel 能中断 pending future。

- **现象**:控制通道发送端被 drop 后,Agent 任务在模型返回前空转 CPU(分支反复就绪)。
- **根因**:两处 `select!` 只处理 `Some(AiControl::Cancel)`,对 `None`(通道关闭)不 `break`,而关闭的 `Receiver::recv()` 立即返回 `None`。
- **依据**:[ai_job.rs:424-435](../../src-tauri/src/ai_job.rs)(FC 路径)与 [:446-457](../../src-tauri/src/ai_job.rs)(文本路径)
- **改法**:抽出 `async fn drive_step<F: Future>(fut: F, ctl_rx: &mut UnboundedReceiver<AiControl>) -> StepOutcome`,三态 `Returned / Cancelled / ChannelClosed`;`ChannelClosed` 视同终止(发 `Done` + `finished = true`),两处复用,消除重复。
- **验收**:`#[tokio::test]` —— 建 `unbounded_channel()` 后 drop 发送端,传入 pending future,断言函数在 100 ms 内返回且未空转(用 `tokio::time::timeout` + poll 计数)。`cargo test` 121 项 + 新增全过。
- **风险**:中(取消/结束语义),须保证正常 Cancel 与正常 Returned 路径行为不变。

- **风险**:低(仅影响解析层;真实存在名为 `run_command` 的可执行文件概率极低)。

- **落地**:新增可测判定 `is_bare_goal_marker(next, active_goal)`(= 无进行中子目标 && 有协议标记 && 解析后无命令);命中时只回喂提示并按 `invalid_steps` 有界计数(防弱模型反复发标记死循环),不再产生「✗ $ GOAL_OK …」失败卡;+1 单测(含"有活动子目标时不走此分支""真命令/普通散文不受影响")。
- **现象**:Agent 收尾时模型只回 `GOAL_OK`(无命令),UI 出现 `✗ $ GOAL_OK 模型未给出可执行命令` 失败卡。
- **根因**:命令解析把该行过滤后命令为空,ai_job 走"模型未给出可执行命令"回喂分支,并把**原始行**当 command 展示。
- **改法**:该分支识别"纯协议标记回复"(`GOAL_OK`/`GOAL_DONE`/`GOAL_FAIL`/`DONE`)时不产生失败步骤卡,只更新子目标状态/回喂提示。
- **验收**:真机复跑出现 GOAL_OK 收尾时,不再出现 `✗ …` 步骤卡。
- **风险**:低。
